# DeliveryBot

面向 Leaves 1.21 的取货机器人插件。它绑定 Leaves 自带假玩家，从登记过的仓库读取库存；支持一次请求多种物品、递归合成中间材料、短途步行与长途鞘翅飞行，最后在玩家附近定向丢出货物并返回原位。

## 运行环境

- Leaves `1.21-46-master@c19e742`（Minecraft 1.21）
- Java 21 或更高
- 不需要 Citizens、ProtocolLib 或其他前置插件
- `leaves.yml` 中必须启用 fake player，且假人上限至少为 1

## 构建

```powershell
.\gradlew.bat build
```

产物位于 `build/libs/deliverybot-0.1.7.jar`。

## 首次配置

1. 把插件 JAR 放入服务端 `plugins` 目录并启动服务端。
2. 确认 Leaves 假人功能已启用。
3. 由拥有 `bukkit.command.bot` 权限的管理员站在停机位置执行：

   ```text
   /deliverybot create DeliveryBot
   ```

   如果已经通过 `/bot create` 创建了假人，则执行：

   ```text
   /deliverybot bind <假人名> confirm
   ```

   `bind` 只能用于 Leaves 假人。Paper API 没有可靠的通用接口区分真人与 Leaves 假人，
   因此不要把在线真人玩家绑定为机器人。

4. 看向仓库箱子、木桶或潜影盒，逐个执行：

   ```text
   /deliverybot warehouse add
   ```

   如果仓库是一片潜影盒或其他容器，可站在中间一次性登记：

   ```text
   /deliverybot warehouse scan
   /deliverybot warehouse scan 16
   ```

   默认半径为 12，最大半径为 24；只扫描已加载区块和 `allowed-containers` 中允许的容器。

5. 把切石机和工作台放在 `workstation-radius` 范围内。
6. 用 `/deliverybot status` 检查绑定、仓库数量和机器人状态。

## 请求格式

```text
机器人 送我 64 石砖
机器人 给我 单个钻石
机器人 给我 1组火把
机器人 给我 一盒石砖
机器人 给我 128个安山岩，128个闪长岩
机器人 给我 2组火把还有单个钻石
机器人 给我 32 minecraft:oak_planks
@快递员 16 铁锭
```

数量单位：

- 不写单位或使用 `个`、`份`：精确物品数量，例如 `128安山岩`、`128个安山岩`。
- `组`：按照该物品的最大堆叠数换算，例如 `2组石砖` 为 128 个。
- `盒`、`箱`：默认按照 27 个完整堆叠换算，可通过 `request.box-slots` 调整。
- `单个`：明确请求 1 个物品。

多物品订单可以使用 `，`、`,`、`、`、`;`、`；` 或“和、还有、以及”连接。机器人会把它作为一个订单处理，只进行一次备货和配送。规划阶段不会立即修改仓库；如果任意一项缺少成品、原料或所需工作方块，整单都会失败且不扣除任何物品。

“一盒”表示散装的 27 组，机器人会逐组丢出，不会自动提供或装填潜影盒。每一项均受 `request.max-amount` 限制，整单还必须能放入机器人 35 格货舱；合成产生的待退库余料也会占用货舱格数。

插件默认加载 Minecraft 1.21 官方简体中文物品名；简称和服务器自定义名称在
`plugins/DeliveryBot/item-aliases.yml` 中维护。修改后执行：

```text
/deliverybot reloadrecipes
```

`/deliverybot request <数量> <物品>` 管理命令目前用于单物品测试；多物品订单请通过聊天发送。

## 库存与合成规则

1. 按订单顺序检查各项，优先使用仓库中的现成物品。
2. 成品不足时递归寻找中间材料，默认最大深度为 6。
3. 每一层先尝试附近的切石机配方，再尝试工作台配方。
4. 前一项产生的中间余料可以继续用于订单中的后一项。
5. 所有物品规划成功后才统一扣料；装货失败时会回滚扣除。
6. 配送取消、玩家离线或寻路失败时，未交付物品和合成余料会随机器人返航退库。

例如请求：

```text
机器人 给我 128个安山岩，128个闪长岩
```

如果没有足够成品，机器人可以按库存和配方依次使用原石、石英合成闪长岩，再用闪长岩和原石合成安山岩。附近必须存在对应配方所需的工作台；请求墙、台阶等切石配方时还需要切石机。

## 移动与交付

- 目标距离不超过 14 格且高度差不超过 3 格时优先步行。
- 路面危险、遇到障碍、目标远离或步行卡住时自动切换为飞行。
- 从高处前往低处时沿目标方向斜线下降，不会先水平飞到目标正上方。
- 接近目标后退出高速滑翔，使用受控速度完成精准停靠。
- 交付时停在玩家约 3 格外，面向玩家并把物品定向丢向玩家。

## 主要配置

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `request.max-amount` | `2304` | 一个订单中每一项换算后的最大数量 |
| `request.box-slots` | `27` | “一盒/一箱”包含的完整堆叠数 |
| `warehouse.scan-radius` | `32` | 配送时查找已登记仓库的范围 |
| `warehouse.workstation-radius` | `16` | 查找切石机和工作台的范围 |
| `warehouse.bulk-register-radius` | `12` | 批量登记仓库的默认半径 |
| `warehouse.bulk-register-max-radius` | `24` | 批量登记命令允许的最大半径 |
| `movement.walk-max-distance` | `14.0` | 优先步行的最大距离 |
| `movement.walk-max-height-difference` | `3.0` | 优先步行的最大高度差 |
| `crafting.max-depth` | `6` | 递归合成最大层数 |
| `delivery.drop-distance` | `3.0` | 丢出物品时与玩家保持的距离 |

升级旧版本时，新配置缺失不会阻止插件启动，插件会使用默认值。若要修改新选项，可参考 JAR 内置的 `config.yml` 手动补入现有配置。

## 误绑定真人的恢复方法

如果执行 `bind` 时误填了真人玩家名，插件可能会把该玩家设为无敌、禁止拾取，并把胸甲和副手替换为机器人鞘翅与无限烟花。不要删除世界中的玩家数据文件，也不要在误绑状态下继续执行配送。

推荐恢复流程：

1. 安装 0.1.7 或更高版本并启动服务器。
2. 让被误绑的玩家保持在线。
3. 从服务器控制台或拥有 `deliverybot.admin` 权限的其他管理员执行：

   ```text
   /deliverybot unbind
   ```

4. 确认该玩家已恢复受伤、拾取、行走和普通背包操作。
5. 创建新的 Leaves 假人，或者确认目标确实是假人后重新绑定：

   ```text
   /deliverybot create DeliveryBot
   /deliverybot bind <在线假人名> confirm
   ```

`unbind` 会取消当前配送和排队订单、删除 `plugins/DeliveryBot/bot.yml` 中的绑定记录、恢复在线目标的实体状态，并仅移除带有 DeliveryBot 标记的鞘翅和烟花。为避免把真人背包误当成机器人货舱，它不会移动、清空或自动退库普通背包物品。

如果已经手动删除了 `bot.yml`，或者已经把机器人改绑到别的实体，`unbind` 无法再定位原玩家。让原玩家上线后执行：

```text
/deliverybot recover <在线玩家名>
```

`recover` 只恢复指定在线玩家的无敌、拾取、滑翔和移动状态，并移除插件标记装备；它不会修改当前机器人绑定，也不会移动普通背包物品。

重要限制：旧版本绑定真人时会直接覆盖原胸甲和副手，插件没有保存这两个物品的副本。`unbind` 和 `recover` 无法还原被覆盖的原物品，只能通过服务器备份、背包备份插件或管理员记录恢复。

为防止再次误绑：

- 游戏内玩家不能把命令执行者本人绑定为机器人。
- 绑定已有实体必须追加 `confirm`。
- Paper API 无法可靠区分真人和 Leaves 假人，因此执行确认命令前仍需由管理员核对名称。

## 当前边界

- 机器人不跨世界配送；每个世界应单独部署机器人。
- 默认 14 格内且高度差不超过 3 格时步行；遇到深坑、水、障碍或卡住会自动转为飞行，可在 `movement` 配置段调整。
- 从高处前往低处时直接沿目标方向斜线下降，不再先水平飞到目标上方；最后 6 格进入受控精准停靠。
- 交付时默认停在玩家约 3 格外，面向玩家并把丢出的物品导向玩家；距离可在 `delivery.drop-distance` 调整。
- 只访问管理员登记、位于扫描半径内并且区块已加载的容器。
- 合成器会递归规划中间材料，每一层都优先尝试切石机，再尝试工作台；默认最多 6 层，可用 `crafting.max-depth` 调整，并带循环配方保护。
- 动态特殊配方、熔炉、锻造台等尚未支持。
- 飞行控制适合室外或较开阔的仓库区域；卡住或超时后会按配置安全返航。
- 建议关闭 Leaves 中允许普通玩家打开或操作假人背包的选项，避免其他插件或玩家干扰货物槽位。
- 首次上服前应在与生产服相同的 Leaves 构建中验证假人的滑翔和丢弃事件行为。

## 0.1.4 更新内容

- 支持聊天中一次请求多种物品，并合并为一次配送。
- 多物品订单采用整单规划，任意一项失败都不会扣料。
- 支持在同一订单的后续条目中复用前面产生的中间余料。
- 保留 0.1.3 的递归合成、盒/组/单个数量单位和高低差斜线飞行行为。

## 0.1.5 更新内容

- 修复批量请求磨制安山岩等需加工物品时，任务可能只有排队反馈但不继续执行的问题。
- 机器人现在会寻找首个取货容器附近可站立的位置，避免把潜影盒方块中心作为移动目标。
- 备货规划异常会向玩家反馈并记录完整服务端日志，不会再静默丢失订单。

## 0.1.6 更新内容

- 修复递归合成在排序材料候选时修改 Java 不可变列表而抛出 `UnsupportedOperationException` 的问题。
- 该问题会影响磨制安山岩等“成品不足，需要继续制作原料”的订单。

## 0.1.7 更新内容

- 新增 `/deliverybot unbind`，用于安全解除绑定并恢复误绑在线玩家的无敌、拾取和移动状态。
- 新增 `/deliverybot recover <在线玩家名>`，可在绑定记录已被修改或删除后单独恢复在线玩家。
- 解绑会移除插件生成的机器人鞘翅和无限烟花；为避免误搬真人物品，不会自动清空或退库普通背包内容。
- `bind` 现在拒绝绑定命令执行者本人，并要求追加 `confirm`，降低误绑真人的风险。
- 插件不会备份绑定前的胸甲和副手；若它们曾被覆盖，需要从服务器备份恢复。
